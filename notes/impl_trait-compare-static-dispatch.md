对，你的两个直觉都非常准确！

**1. 为什么这种写法不支持？**
因为在返回类型位置写 `-> impl Summary`，并不意味着函数可以返回“任何”实现了该 Trait 的类型。相反，它的意思是：**函数会返回“某一个特定的、唯一的具体类型”，只是为了代码整洁或者隐藏内部细节，我不把这个类型写明出来而已。**

Rust 是一门静态类型语言，在编译期必须确切知道每个函数的返回值到底占用多少字节的内存。如果你在 `if` 分支里返回 `NewsArticle`，在 `else` 分支里返回 `Tweet`，这两个结构体的内存大小和布局是不同的，编译器无法为这个函数确定一个统一的返回类型，因此直接报错。

> **如何解决？** 如果确实需要根据条件返回不同类型，必须使用**运行期多态（动态派发）**，返回一个指针（Trait Object），比如：
> `-> Box<dyn Summary>`

---

**2. `impl Summary` 是不是有点像 C++ 的模板实现的编译期多态？**
**完全正确，底层机制如出一辙！**

在参数位置写 `fn notify(item: impl Summary)`，其实就是泛型 `fn notify<T: Summary>(item: T)` 的语法糖。

它和 C++ 模板一样，使用的是**编译期多态（静态派发，Static Dispatch）**。
在 Rust 中，这个过程叫作**单态化（Monomorphization）**。当你在代码中分别传入 `Tweet` 和 `NewsArticle` 调用 `notify` 时，Rust 编译器会在编译期自动为你生成两份完全独立的代码：
* `notify_for_tweet(item: Tweet)`
* `notify_for_news_article(item: NewsArticle)`

**相同点（与 C++ 模板）：**
* **零成本抽象**：由于在编译期就已经确定了具体类型，没有运行时的查表（虚函数表 vtable）开销，执行速度极快，且极其容易被编译器内联优化。
* **代码膨胀**：生成了多份代码，编译出来的二进制文件会变大。

**不同点：**
* C++ 传统的模板是“鸭子类型（Duck Typing）”，传什么进去都在编译展开时才报错，报错信息经常是一座长篇大论的大山。
* Rust 的 `impl Trait / Trait Bound` 更像是 C++20 引入的 **Concepts**。你在声明参数时就加上了契约（`Summary`），如果在调用处传入未实现该 trait 的类型，Rust 在“调用点”就会立刻给你精准而简明扼要的报错，而不需要等到内部展开。
